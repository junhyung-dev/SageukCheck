# 미션 2 산출물 현황

미션 2 때 만든 산출물을 열어 확인한 내용이다. 최종 제출 작업의 출발점으로 쓴다.
"확인한 사실"은 파일을 직접 열어 본 것이고, "확인 필요"는 받은 자료로는 답할 수 없는 것이다.

- 검토일: 2026-11-09
- 대상 파일 (팀 공유 폴더, 저장소에는 없음)
  - `미션2_사극체크.json` (워크플로우 설정, `configVer: 1`, 2026-11-06 내보냄)
  - `경크크_미션2_set01.pdf` ~ `경크크_미션2_set05.pdf`
  - `경크크_미션2_answer.json`, `경크크_미션2_유형표.xlsx`, `경크크_미션2_설계서.pdf`

## 1. 업무 정의

- 업무: 사극 대본 속 역사 주장 1건을 역사 사료와 대조해 1차 판정한다.
- 판정 단위: 대본 장면 1개 = PDF 1개 = 판정 1건
- 문서 3종
  - 사극 촬영 대본 (필수): AI로 창작한 대본
  - 역사 사료 (필수): 조선왕조실록 기사를 바탕으로 만든 문서
  - 역사 고증 검토 요청서 (선택)
- 판정 기준 (설계서): 사료가 지지하면 일치, 직접 모순이면 충돌, 누락 · 판독 불가 · 근거 부족이면 검토 필요

## 2. 워크플로우 구조 (`미션2_사극체크.json`)

```
PDF 1개
  → Parse            OCR 강제(ocrMode: force), 출력 html + text
  → Classify         사극문서_분류, split: CONTINUITY
      script            → Extract 대본_정보추출
      historical_source → Extract 사료_정보추출
      review_request    → Extract 검토요청_정보추출
      Other             → 연결된 노드 없음
  → Merge            고증자료_병합
  → Instruct         역사고증_판정 (enum: 일치 / 충돌 / 검토 필요)
```

### Extract 항목

| 스키마 | 항목 |
|---|---|
| 대본_정보추출 | `scene_id`, `script_period`, `script_claim`, `script_person` |
| 사료_정보추출 | `source_reference`, `source_event`, `source_evidence` |
| 검토요청_정보추출 | `requested_check` |

- 모든 항목에 설명이 적혀 있다.
- 세 스키마 모두 `manyRows: true`다.

### Instruct (역사고증_판정)

- 위 8개 값을 `@변수`로 받는다.
- 판정 기준
  - 검토 필요: 대본 또는 사료 누락, 판독 불가, 사료로 뒷받침 · 반박 불가, 사건 · 인물 불일치, 해석 모호 · 사료 간 충돌, 분류 · 추출 불완전
  - 충돌: 대본의 주장이 사료의 명시적 기록과 모순
  - 일치: 대본의 주장이 사료에서 명확하게 확인됨
- 지침: 제공된 문서만 근거로 쓰고, 외부 지식으로 보충하지 않으며, 근거가 부족하면 검토 필요로 판정한다.
- 출력: 5개 키를 `key: value` 텍스트 줄로 출력한다. `decision`은 enum으로 제한된다.

## 3. 출력 키

설계서, 워크플로우 프롬프트, 정답지가 같은 5개 키를 쓴다.

| 키 | 형식 (설계서) |
|---|---|
| `scene_id` | 문자열, 예: `SC-001` |
| `decision` | `일치` \| `충돌` \| `검토 필요` |
| `reason` | 문자열 1~2문장 |
| `source_reference` | 문자열, 사료명 · 권 · 날짜 · ID, 없으면 빈 값 |
| `missing_documents` | 문자열 배열, 없으면 `[]` |

결정값 표기 `검토 필요`는 설계서, 워크플로우 enum, 정답지에서 모두 같다.

## 4. 데이터셋과 정답

| case | 파일 | 페이지 구성 | 정답 | 유형표의 유형 |
|---|---|---|---|---|
| A | set01 | 대본 p1-2, 사료 p3 | 일치 | ① 단순 |
| B | set02 | 대본 p1-3, 사료 p4-7 | 충돌 | ② 양식·문맥 다양성 |
| C | set03 | 대본 p1-2, 사료 p3-5, 요청서 p6 | 일치 | ③ 문서 결합 |
| D | set04 | 대본 p1-2, 사료 p3-4 (흐린 이미지) | 검토 필요 | ④ 저품질 |
| E | set05 | 대본 p1-2만 | 검토 필요 | ⑤ 예외·함정 |

- 문서 수: 2 + 2 + 3 + 2 + 1 = 10건

### case별 근거

- A: 대본 "올해(세종 25년) 스물여덟 자의 언문을 만들었네" ↔ 세종실록 102권 kda_12512030_002 「上親制諺文二十八字」
- B: 대본 "최만리가 언문 제작을 적극 찬성하는 상소를 올렸다" ↔ 세종실록 103권 kda_12602020_001 기사명 "최만리 등이 언문 제작의 부당함을 아뢰다"
- C: 대본 세종 28년 9월 《훈민정음》 완성 ↔ 세종실록 113권 kda_12809029_004 「是月, 訓民正音成」
- D: 대본에 최항 · 박팽년의 《운회》 번역 주장이 있다. 사료 p3-4의 원문 · 국문이 흐린 이미지라 읽을 수 없고, 출처 줄에 "원본 표제 및 기사번호는 스캔에서 식별 불가"라고 적혀 있다.
- E: 대본에 세종 26년 2월 최항 · 박팽년 등에게 《운회》 번역을 명했다는 대사가 있다. 사료가 없다.

### set04 파일 버전 주의

같은 이름 계열의 set04가 두 가지 있다. 정답지와 유형표는 **저품질 버전** 기준이다.

| 버전 | 위치 | 페이지 | 사료 | md5 |
|---|---|---|---|---|
| 저품질 (정답지 기준) | `경크크_미션2_set04.pdf` | 4 | 흐린 이미지, 기사 ID 없음 | `46d47db8592eb0c926dc4e71a8fef0f4` |
| 깨끗한 텍스트 | `SageukCheck_set04.pdf` = 저장소 `public/samples/set04_sc004.pdf` | 3 | 세종실록 103권 kda_12602016_001 텍스트 | `468ab922fb6976e95b5294ae4ccdac4d` |

- 저장소의 `README.md`와 `src/lib/sample-datasets.ts`는 깨끗한 버전을 기준으로 SC-004를 "일치 검증"으로 설명한다. 정답지(`검토 필요`)와 다르다.
- 저장소의 나머지 샘플(set01, 02, 03, 05)은 미션 2 제출 파일과 md5가 같다.

## 6. 확인 필요

- 운영진 채점기가 Instruct의 `key: value` 텍스트 출력에서 키와 배열 값을 어떻게 읽는지 (받은 자료에 없음)
- `reason`처럼 서술형인 값을 어떤 방식으로 정답과 비교하는지 (받은 자료에 없음)
- `manyRows: true`일 때 대본에서 주장이 여러 행으로 추출되면 Instruct에 어떻게 전달되는지 (실행 결과로 확인)
